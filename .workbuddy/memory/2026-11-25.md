## 修复运行期崩溃（"异常退出"，0xC0000005 @ RVA 0x501FD7）

现象：编译通过后一启动就崩（0.1~0.5s，无窗口、无输出），WER 每次都是 Project1.exe / 0xc0000005 / 偏移 0x501fd7。

定位手段（可复用）：
- 本机无 cdb/gdb 可用；MSBuild 被安全策略拦截，无法自己重编。
- 用 dbghelp + ctypes 解析：SymLoadModuleEx 要传**独立基址**（如 0x200000000），否则与 python.exe 的 0x140000000 冲突导致 SymFromAddr 报 err=87（但 SymGetLineFromAddr 仍能给出误导性的行号）。
- 用 .pdata 函数表 + 符号定位到函数边界：崩溃点在 `Assimp::Logger::info +0x57`。
- 该函数 96 字节：`strlen(msg) > MAX_LOG_MESSAGE_LENGTH(0x400)` 触发 `ai_assert(false)`(DefaultLogger.cpp:179)，否则走虚函数 `OnInfo`；崩溃指令是 `call qword ptr [rax+0x20]`，rax 来自 `[this]` → this 上的 vptr 是 0。

根因：源1.cpp 第 96 行把 `Model ourModel("backpack.obj");` 写在**全局作用域**。静态初始化阶段它就构造 Model → assimp 导入 → assimp 写日志 `DefaultLogger::get()->info(...)`，而 assimp 的 `NullLogger DefaultLogger::s_pNullLogger;`（DefaultLogger.cpp）此时候选构造还没执行，vptr 仍为 0（`m_pLogger` 指向它是链接期常量，不受顺序影响）→ 虚调用崩溃。即使顺序侥幸正确，`Mesh::setupMesh` 里的 glGenVertexArrays 也会在无 GL 上下文时调用空指针。

修复（源1.cpp）：
1. 全局 `Model ourModel(...)` 移入 main()，放在 `glfwMakeContextCurrent` + `gladLoadGLLoader` 之后。
2. 顺带修正绘制顺序：模型要用主着色器画，必须在 `light.use()` 之前、`shaderProgram` 仍绑定时 `setMat4("model")` + `ourModel.Draw()`（原代码把 model uniform 传给了 light 程序）。

经验：这个工程里任何"需要 GL 上下文/第三方库全局单例"的对象，都不能定义在全局作用域，必须放进 main 且在建好上下文之后。

## 换自己的 obj 后崩溃（0xC0000005，RIP 在非模块内存）

现象：工程改名 666.exe，`Model ourModel("未命名.obj")` 后启动 1s 崩；stdout 有 `ERROR::ASSIMP:: Unable to open file "未命?obj"`；VS 显示"帧不在模块中"，寄存器几乎全 0。

定位（自写调试器，ctypes + DEBUG_ONLY_THIS_PROCESS）：
- DEBUG_EVENT 的 union 在 x64 是 offset 16；**事件码 1=EXCEPTION、3=CREATE_PROCESS、5=EXIT_PROCESS、6=LOAD_DLL**（踩过坑）。
- 用 VirtualQueryEx 查崩溃地址：MEM_PRIVATE + PAGE_EXECUTE_READWRITE → 显卡驱动 JIT 出来的着色器代码。
- 反汇编该处：`mov rsi,[rsi+0x308]` 后 `mov edi,[rsi]`，RSI=0 → 读 0x0。即驱动在取顶点属性时拿到空指针。

根因（与 obj 无关）：`vertices[]` 数组被注释掉、`glBufferData` 也被注释掉，VBO 是 0 字节的空缓冲；`glDrawArrays(GL_TRIANGLES, 0, 36)` 让驱动从空绑定取顶点 → JIT 代码空指针崩溃。

第二个独立问题：`未命名.obj` 根本打不开。assimp 3.1.1 的 `Importer::ReadFile(const char*)` 走 ANSI `fopen`，而 源1.cpp 已存成 UTF-8(BOM)，中文名变成 UTF-8 字节 → 找不到文件（只报错不崩）。另外 Blender 导出的 obj 里 `mtllib 未命名.mtl` 指向的 mtl 不存在。

修复：
1. 恢复 `float vertices[] = {...}` 与 `glBufferData(...)`（36 顶点立方体的数据）。
2. obj 改 ASCII 名：`未命名.obj` → `cube.obj`，内部 `mtllib cube.mtl`，并补一个默认 `cube.mtl`（newmtl Material + Kd/Ks/illum 2）。
3. 源1.cpp 里 `Model ourModel("cube.obj")`。

经验：源1.cpp 现在是 **UTF-8 with BOM**（VS 保存的），此前是 GBK；改文件时注意保持编码，往里面写中文注释不要再混 GBK。assimp 3.1.1 + 中文路径在 Windows 上不可用，模型文件一律用 ASCII 文件名。
