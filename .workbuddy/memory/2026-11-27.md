## Project1（LearnOpenGL / VS2019 v142 x64）修复 game.cpp 分离重构后的链接失败

- 复现命令：用 VS2019 的 cl.exe 手工编译全部 TU 再链接，得到
  `LNK2005: TextureFromFile 已经在 game.obj 中定义`。
- 根因：`model.cpp` 里的 `TextureFromFile` 是非 inline 自由函数，`game.cpp` 与 `源1.cpp`
  两个 TU 都 `#include "model.cpp"` → 两份定义。其余类都是类体内定义（隐式 inline），所以只有它炸。
- 修复方案：
  - 新增 `shaderr.h`（仅声明 Shader），`shaderr.cpp` 改为真正的实现 TU（含析构、isValid、禁止拷贝）。
  - `mesh.cpp` / `model.cpp` 的 `#include "shaderr.cpp"` 改为 `"shaderr.h"`。
  - `TextureFromFile` 标记 `inline`；`Model::loadModel` 的 directory 提取改为无分隔符时用 "."。
  - `game.cpp` 重写为完整的 `Game` 类（window/GL/scene 初始化、RAII 清理、静态回调 + user pointer、
    渲染循环）+ `main()`；纯 ASCII 注释，避免 GBK 乱码。
  - `源1.cpp` 在 vcxproj 中 `ExcludedFromBuild=true`（保留可见，只有一个 main）。
- 验证：cl 编译 + 链接成 666.exe 成功；运行 8s 无 shader/assimp 报错输出，渲染正常。
- 结论：**这个工程里 .cpp 被当头文件用**，任何"被多个 TU include 的 .cpp"里的非 inline 自由函数/全局变量
  都会 LNK2005；同理不能再让两个文件同时定义 main。

## 第五次：给光标加屏幕中心准心

- 新增 `crosshair_vertex` / `crosshair_fragment`（纯 ASCII，VS 里作 None 项登记，与 vertex/fragmenttex 同级）。
- **不需要 VBO**：顶点着色器用 `gl_VertexID` 生成 4 角 quad，CPU 只发 `glDrawArrays(GL_TRIANGLE_STRIP, 0, 4)`；
  core profile 仍必须绑一个空 VAO（`crosshairVAO`，initScene 里 glGenVertexArrays）。
- 片段着色器用 SDF（横条 boxSDF ∪ 竖条 boxSDF），`fwidth(d)` 做 1px 抗锯齿，alpha 混合。
- 准心用**两层绘制**（先 rim 后 core，靠 uThickness/uColor 区分），比"用收缩 SDF 做描边"稳：
  后者在 `px*1.2` 收缩量小于 fwidth 过渡带时白核永远到不了 1.0，实测被打成 215 灰。
- 尺寸常量在 game.cpp 匿名空间：`kCrosshairHalfLengthPx=10`、`kCrosshairRimThickness=0.22`、
  `kCrosshairCoreThickness=0.13`（厚度 = 比例 × 半长，单位 NDC uv）。
- 位置换算：`uHalfSize = kCrosshairHalfLengthPx * 2 / fbHeight`（1.0 NDC = fbHeight/2 px），
  **x 方向必须除以 aspect**（不是乘）——乘了会得到 36×20 的扁十字，实测踩过。
- render() 最后调用 `renderCrosshair()`：关深度测试、开混合，画完恢复；X 键切换显隐（边沿检测 `crosshairToggleHeld`）。
- 验证：cl 编译零警告；截屏像素分析 bbox 20×20、中心与客户区中心一致（误差 0.5px）、白核 2px 宽 + 约 1px 暗边。
- 截图测坐标要点：Python 进程要先 `SetProcessDPIAware()`，否则 GetClientRect 返回的是被 1.5 倍 DPI 缩放后的逻辑尺寸。
